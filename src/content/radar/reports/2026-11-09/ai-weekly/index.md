## 3. AI Agent 生态

OpenClaw 及同赛道 Agent 项目本周呈现“安全边界加固”与“多代理协作”双线推进的特征：

- **OpenClaw**：作为私导向的 Agent 框架，本周连续发布两个版本，重点解决私日志脱敏、多频道协作及会话状态与安全边界的并发处理。其高 PR 密度（单日 50 条）表明社区对可信 Agent 基础设施的需求旺盛。
- **Hermes (NousResearch)**：多租户架构与跨网关 Bot 协作持续深化，子代理状态存储与轮次准入事务（如 #151554）成为可观测性与一致性的关键尝试；插件安全机制（如召回插件仍可被启用的漏洞修复）体现企业级 Agent 对治理的重视。
- **Claude Code Skills (Anthropic)**：作为 Claude Code 的技能模块化扩展，社区反映 Skills 压缩后重放会导致陈旧参数重复执行（#85138），技能版本管理与状态一致性成为 Agent 插件生态的共性难题。
- **同赛道共性**：子代理可靠性（状态误报、挂起、权限执行不一致）、MCP/ACP 协议工具发现与缓存失效、破坏性操作确认与回滚机制，已成为 AI Agent 生态从“Demo 阶段”迈向“生产可用”的核心门槛。

## 4. 开源趋势

基于本周 GitHub 及 AI 社区活动，以下技术方向获得最高关注度：

1. **MCP / ACP 协议标准化与可观测性**：多个 CLI 工具（Claude Code、Gemini CLI、OpenCode、Hermes）集中反映 MCP 连接器工具列表缓存失效、OAuth 持久化及资源读取转发问题，协议层的稳定性与诊断能力成为刚需。
2. **安全沙箱与破坏性操作防护**：从 User-Agent 泄露邮箱、模型误删交接记录，到误操作销毁 systemd 导致重大损失，社区强烈要求破坏性命令确认、回滚机制及细粒度权限策略。
3. **子代理（Subagent）可靠性与状态一致性**：子代理超时中断仍上报成功、通用代理无限挂起、UI 状态丢失等问题普遍存在，状态机设计与可观测性成为 Agent 编排的核心课题。
4. **跨平台终端与 PTY 协议升级**：Windows 沙箱启动失败、macOS Seatbelt 崩溃、Linux TMPDIR/符号链接权限问题频发；OpenCode 发布的 @opencode/pty@0.5.0 显示出底层终端交互协议正在被重新审视。
5. **配额透明度与计费信任**：OpenCode 免费层配额争议（333 条评论）及 Codex $10 额度异常耗尽讨论，表明开发者正从“尝鲜”转向“生产化脚本化”，对成本可预测性要求显著提升。
